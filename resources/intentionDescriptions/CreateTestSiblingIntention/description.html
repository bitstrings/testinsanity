Creates the test sibling that the configured TestInsanity naming scheme expects but that does not exist yet: the test class for the subject class, or the test method for the subject method.

One entry is offered per scheme that is still missing its test class, so a project with a unit scheme and an integration scheme can create either. When more than one is missing, a chooser lists them by scheme name; when only one is, it is named directly in the intention text.

The name is generated from the test class and test method patterns of that scheme, configured in Settings -> Tools -> TestInsanity. The test class is created under the package of the subject class, in the module's first test source root; when the module has none, in the module declared as its test module, or in the single dependent module that has test roots. The test method is annotated with the first enabled test framework annotation that resolves in the test module.

Available on a subject class or a subject method in Java sources only, and only while the sibling is missing.
